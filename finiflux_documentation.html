FINIFLUX, the differentiable Python edition

A differentiable reimplementation of the FINIFLUX radon mass-balance model. It estimates groundwater discharge and hyporheic exchange to rivers from radon-222 profiles, reach by reach.

Overview

The whole forward model is built from differentiable tensor operations: steady-state 1-D advection–reaction transport, solved with an implicit Petrov–Galerkin (upwinded) linear finite-element scheme. This replaces the external BEOPEST optimizer of the original MATLAB code. Gradients of the data misfit with respect to the parameters come from backpropagation, so the inversion optimizes directly.

It ships as two parallel packages with identical physics, inputs and outputs. Only the tensor backend and optimizer differ:

  • finiflux_pytorch/: PyTorch backend (Adam warm-start, then L-BFGS).
  • finiflux_tensorflow/: TensorFlow backend (Adam via GradientTape).

For each reach, the model estimates groundwater inflow I, hyporheic-zone depth h and hyporheic-zone mean residence time t_h.

Background and references

Radon-222 is a naturally occurring, conservative groundwater tracer. Groundwater is strongly enriched in radon compared with river water, so the radon profile along a stream records where and how much groundwater enters. FINIFLUX closes a radon mass balance reach by reach. It accounts for groundwater inflow, hyporheic exchange, degassing to the atmosphere, radioactive decay and tributary inflow, and inverts the measured radon profile into a spatially resolved estimate of groundwater discharge.

  • Frei, S. & Gilfedder, B.S. (2015). FINIFLUX: An implicit finite element model for quantification of groundwater fluxes and hyporheic exchange in streams and rivers using radon. Water Resources Research, 51, 6776–6786. doi:10.1002/2015WR017212
  • Frei, S., Durejka, S., Le Lay, H., Thomas, Z. & Gilfedder, B.S. (2019). Quantification of hyporheic nitrate removal at the reach scale: Exposure times versus residence times. Water Resources Research, 55(11), 9808–9825. doi:10.1029/2019WR025540

Installation

Download FINIFLUX for Python (.zip)

The download contains run_FINIFLUX.py, the PyTorch and TensorFlow packages, the README and an example input file (FINIFLUX.xlsx, the Schaefer et al. dataset). Unzip it and install the requirements:

It requires Python 3 with NumPy, openpyxl, matplotlib and one tensor backend:

# PyTorch backend
pip install torch numpy openpyxl matplotlib

# or TensorFlow backend (use an arch-matched wheel, e.g. arm64 on Apple Silicon)
pip install tensorflow numpy openpyxl matplotlib

No editable install is needed. The launcher puts the chosen package on sys.path.

Quick start

run_FINIFLUX.py at the repository root is the only file you run. It finds FINIFLUX.xlsx, selects the backend, reads the input, runs the model, writes the output files and makes the plots.

python run_FINIFLUX.py                       # invert, PyTorch, reads FINIFLUX.xlsx -> results/
python run_FINIFLUX.py --backend tensorflow  # same via TensorFlow
python run_FINIFLUX.py --mode forward        # one forward run, no fitting
python run_FINIFLUX.py --input other.xlsx --out run2 --show
python run_FINIFLUX.py --uncertainty --rn-sigma-rel 0.1   # fit + posterior UQ, 10% meas. σ
python run_FINIFLUX.py --endmember           # add GW-endmember uncertainty band
python run_FINIFLUX.py --bedform-depth       # compute h from bedform heights (col N)

The defaults are in the CONFIG dictionary at the top of the launcher, and every entry has a matching command-line flag (--backend, --mode, --out, --plot, --show, --adam, --lbfgs, --iter, --lr, --smooth, --quiet, plus the uncertainty, endmember and bedform flags).

Each package can also be run directly or used as a library:

python -m finiflux_torch.cli invert FINIFLUX.xlsx
python -m finiflux_tf.cli    invert FINIFLUX.xlsx
from finiflux_torch import read_input, fit, write_results, plot_all, estimate_uncertainty
data   = read_input("FINIFLUX.xlsx")
result = fit(data)
write_results(result, "results/")

Governing equation

Steady state, for each reach:

Q dC/dx = [ I·c_gw + α1 + (Q_in/L)·c_in ]            (sources)
        − [ I + α2 + k·w + λ·d·w + Q_in/L ]·C        (sinks ∝ C)

C is radon (Bq/m³), Q discharge (m³/s), w width, d depth, λ = 0.18/86400 s⁻¹ the ²²²Rn decay constant, c_gw the groundwater endmember, and Q_in, L and c_in the tributary inflow rate, length and concentration.

  • Hyporheic source and loss: production α1 and loss α2 (proportional to C) depend on h, porosity, w, t_h and the residence-time distribution (RTD).
  • Degassing k: from O'Connor & Dobbins (1958), Negulescu & Rojanski (1969), or user-supplied values.

Finite-element model

Linear (P1) elements. For each element, a reaction (consistent mass) matrix, a Galerkin advection matrix, a Petrov–Galerkin upwind correction scaled by β, and a load vector are assembled into dense A and b tensors. The upstream boundary condition C(node₁) = Rn(node₁) is imposed with the penalty method, and the system is solved with torch.linalg.solve or tf.linalg.solve. Gradients flow through the solve.

Residence-time distributions

All three are implemented and reduce to a smooth pair (α1, α2), so gradients flow to h and t_h:

  • Exponential: closed form, α1 = γ·h·w·por/(1+λ·t_h) and α2 = λ·h·w·por/(1+λ·t_h).
  • Gamma: closed-form Laplace transform L = (1+λ·t_h/a)^−a with shape a.
  • Truncated power law: differentiable quadrature, a faithful port of the MATLAB pwr.m.

Inverse problem

  • Unknowns per reach, held in log space for positivity and scaling: θ = (log I, log h, log t_h).
  • Loss = data misfit + regularization.
    • Data misfit Σ w_j·(C − Rn_obs)² with weights normalized by the detection limit, w_j = 1/max(Rn_obs_j, detection_limit)², so large and small activities contribute comparably.
    • Regularization (configurable, small or zero by default): a smoothness penalty across neighbouring reaches and/or a light pull toward the initial values.
  • Parameter bounds, enforced every iteration: I from 1e-10 to 1e-2 m³/(m·s), h from 1e-3 to 1.0 m, t_h from 60 to 43 200 s.
  • Optimizer: PyTorch uses Adam followed by L-BFGS. TensorFlow uses Adam, because Keras has no L-BFGS.

Why differentiable? In the original FINIFLUX, Tikhonov regularization toward prior values is how BEOPEST stabilizes the fit. Here the regularization is a design choice, not a copy of PEST. Log-space parameters and the normalized misfit do the stabilizing, and the smoothness and prior penalties are small by default so the data drive the fit.

Uncertainty quantification

The optional module uncertainty.py builds the Laplace (Gauss–Newton) posterior covariance of the fitted parameters on top of the same differentiable forward model. It doesn't change the forward or inverse code.

  • The calibrated θ is treated as the maximum a posteriori estimate of a Gaussian-noise inverse problem, with Σ = H(θ̂)⁻¹.
  • method="gauss_newton" (default, always positive semi-definite) uses H ≈ Jᵀ Σ⁻¹ J + prior. method="full" uses the exact autodiff Hessian.
  • The noise σ defaults to max(obs, detection_limit). You can supply a known measurement σ instead (--rn-sigma-abs or --rn-sigma-rel). calibrate_sigma=True rescales by χ²/(N−p).
  • Outputs per reach: best estimate, standard deviation and credible interval, plus .summary(), .correlation() and an identifiability_report(). The report shows the trade-off between I, h and t_h as near-zero Hessian eigenvalues.
from finiflux_torch import estimate_uncertainty, UncertaintyConfig
unc = estimate_uncertainty(data, result, config=UncertaintyConfig())

Groundwater endmember uncertainty

The groundwater endmember c_gw is a second, independent source of error, and usually the largest uncertainty in radon-based inflow estimates. Column U of FINIFLUX.xlsx holds the endmember standard deviation for each reach. endmember_uncertainty(data, config, p_low, p_high) re-fits the inversion with the low and high percentile endmembers and returns the resulting range of I per reach. A higher endmember means less inflow for the same observed radon. The percentiles can be changed with --em-p-low and --em-p-high. The result is drawn as a separate second figure.

Hyporheic depth from bedforms

Instead of estimating h, --bedform-depth calculates it for each reach from bedform heights, with the Elliott & Brooks (1997, after Fehlman 1985) dynamic-head relation h_m = 0.28·(Ū²/2g)·(H/0.34d)^m. Column N is then read as the bedform height H. h becomes fixed, so the inversion fits only I and t_h.

Input file

FINIFLUX.xlsx has a single sheet, read by label and column letter. This makes it robust to row shifts and works for any number of points. You can build it with the FINIFLUX input builder.

ColumnsContents
B/COptions: degassing model, hyporheic zone on/off, RTD model, gamma alpha, upstream weighting β, upstream radon (boundary condition), detection limit.
F, GSampling points: location (m) and measured radon (Bq/m³). Every point is a measurement location, and the modelled radon at each point is compared directly with the observation.
I–TReaches, one fewer than points: reach length, depth, width, groundwater endmember, hyporheic depth or bedform height, porosity, tributary discharge, length and concentration, discharge, and user-defined k.
U (optional)Groundwater endmember standard deviation per reach, used by the endmember uncertainty analysis.

Outputs

Each run writes to the --out folder: gw_inflow.dat (I), depth_hz.dat (h), rtimes_hz.dat (t_h) and Rn_modeled.csv (location and modelled radon). --uncertainty adds uncertainty.csv, and --endmember adds a second figure and endmember_uncertainty.csv.

The main figure, finiflux_plots.png, has five panels:

  1. Simulated against observed radon, with r and RMSE. A shaded ±σ band is added when a known measurement σ is given.
  2. Estimated groundwater inflow I along the river, with a credible-interval band.
  3. Estimated hyporheic depth h, with a credible-interval band.
  4. Estimated residence time t_h, with a credible-interval band.
  5. Cumulative groundwater inflow Σ(I_i·Δx_i) along the river compared with the observed discharge gain ΔQ (a water-balance check), with a credible band from the log I covariance.

When uncertainty bands are drawn, the parameter panels take their y-range from the best estimates. A poorly constrained interval therefore can't flatten the estimate curve; the exact bounds are in uncertainty.csv.

Package layout

run_FINIFLUX.py              # single launcher: backend select, run, write, plot

finiflux_pytorch/finiflux_torch/
  io.py            # label-based FINIFLUX.xlsx reader + native writers (pure NumPy/openpyxl)
  degassing.py     # k models 1/2/3
  hyporheic.py     # α1/α2 for exp + gamma + power-law RTD (differentiable)
  forward.py       # FE assemble + penalty BC + linear solve -> C (autodiff)
  inverse.py       # log-params, normalized misfit + reg, Adam -> L-BFGS
  uncertainty.py   # Laplace / Gauss-Newton posterior covariance (add-on)
  endmember.py     # GW-endmember (c_gw) uncertainty via percentile re-fits
  bedform.py       # Elliott-Brooks hyporheic depth h from bedform height H
  plotting.py      # plot_radon / plot_parameters / plot_uncertainty / plot_cumulative_gw
  cli.py           # python -m finiflux_torch.cli forward|invert
  tests/test_smoke.py

finiflux_tensorflow/finiflux_tf/   # line-for-line mirror; tf.scatter_nd + tf.linalg.solve,
                                    # tf.GradientTape + Keras Adam

plotting.py and io.py are pure NumPy and identical in both packages. uncertainty.py has the same interface and statistics in both; only the autodiff backend differs.
